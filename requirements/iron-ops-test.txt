# What iron-ops' OWN pytest suite needs, on top of compiler-stack.txt. Installed only by
# `dev.py setup --iron-ops-tests` for the local `dev.py test-npu-iron-ops` path.
#
# CI does not install this. The flm compile and the prebuilt NPU package oracles
# use NumPy. NPU e2e jobs use `npu-test-runtime` (numpy + ml-dtypes) and dispatch
# the prebuilt package; they never run iron-ops pytest.
#
# torch: iron-ops' own golden references and its test harness are written against it.
# CPU only -- nothing here runs on a GPU. The compiler and package jobs do not import it.
#
# Pinned by exact wheel URL rather than `--extra-index-url https://download.pytorch.org/whl/cpu`
# plus a version. Two reasons: a plain `torch` on Linux resolves to the CUDA wheel and drags
# in ~2.5 GB of nvidia-* deps for kernels we never run; and that index ALSO publishes `cmake`
# (3.25), which would shadow PyPI's for compiler-stack.txt's `cmake>=3.30` -- uv refuses to
# resolve at all, and pip is one `--index-strategy` away from silently picking it. A URL pin
# puts torch on the path without giving a second index a say in anything else.
# cp312: the stack pins Python 3.12 throughout (tomllib, setup-python, the lock).
torch @ https://download.pytorch.org/whl/cpu/torch-2.9.1%2Bcpu-cp312-cp312-manylinux_2_28_x86_64.whl ; sys_platform == "linux"
torch @ https://download.pytorch.org/whl/cpu/torch-2.9.1%2Bcpu-cp312-cp312-win_amd64.whl ; sys_platform == "win32"
